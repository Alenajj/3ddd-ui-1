# 3ddd-ui — правила для Claude-разработчика

Библиотека компонентов 3ddd.ru на **Angular 22** + Storybook 10. Разработчики сайта переходят с Angular 16.2 на 22; компоненты утверждаются здесь и потом передаются им.

## Как идёт работа
- Компоненты делаются пачками по 3–5 штук. Каждая пачка — отдельная ветка и pull request.
- Эталон — только Figma «Кит для ии 2026». Размеры, токены и состояния снимаются прямо с кита. Папку `claude-design/` из 3ddd-design-system не использовать: это прототипы, не эталон.
- В каждом PR: код компонента, стили, истории Storybook со всеми вариантами и состояниями. Алёна сверяет вид с Figma, разработчик — код. Сливаем после одобрения обоих.
- Токены не править здесь: `npm run sync-tokens` копирует их из `../3ddd-design-system/dist/css`.

## Angular 22
- Только standalone-компоненты, без NgModule.
- Входы и выходы — сигнальные API: `input()`, `output()`, `model()`; производные значения — `computed()`.
- Шаблоны — встроенный control flow: `@if`, `@for` (с `track`), `@switch`. Не `*ngIf` / `*ngFor`.
- `ChangeDetectionStrategy.OnPush` и код, совместимый с работой без zone.js.
- Токены и компоненты передаются разработчикам вместе, одним пакетом. Отдельно токены не отдаём.

## Источник правды
- Figma «Кит для ии 2026» (teNJDzZsG4TTcDfI1P6fAx): токены и компоненты.
- Старый «2025 Кит» — только для справки, там компоненты на примитивах.
- Эталон — только Figma. Компоненты 3ddd-ui снимаются прямо с кита, Storybook сверяется только с Figma.
- Папка `claude-design/` (артефакт «Дизайн-система 3ddd» в Claude Design) — для прототипов и экспериментов, НЕ эталон. Код оттуда не переносить, ошибки там на код не влияют.
- Имена компонентов в Figma «Семейство / Вариант». В коде — `ui-<семейство>` плюс свойство варианта (например, `<ui-like-button type="top">`).
- Правила в папке `docs/`: `component-rules.md` (компоненты, иконки, цвет иконок, Menu Item с Hit area, фильтры), `layout-rules.md` (раскладка и отступы), `typography.md` (текстовые стили), `naming-rules.md` (имена компонентов, иконок, токенов).

## Сайт состоит из двух частей
- **Angular** (каталог, модель, галереи, блог, топ, царь горы, ИИ-поиск): используем компоненты.
- **Старая серверная часть** (форум, /work, страница работы в галерее): Angular-компонентов там нет. Нужны те же стили в виде CSS-классов (`.like-btn.like-btn--primary`).
- Поэтому стили каждого компонента пишутся так, чтобы их можно было подключить и как класс, без Angular.

## Токены
- Токены — глобальные CSS-переменные, объявлены один раз (`:root`). В компонентах только `var(--…)`.
- Никаких «сырых» цветов, отступов и радиусов в стилях компонентов.
- В Figma space и radius названы по значению (space/8, radius/full). В CSS это `--space-8`, `--radius-full`.
- Адаптивные значения (Desktop/Mobile) приходят из коллекции Responsive: переменная переопределяется в media query, а не в компоненте.
- Примитивы `--gray-*`, `--blue-*`, `--green-*`, `--n-*` уже есть на сайте. Не менять, семантические токены ссылаются на них.

## Анимация переходов состояний — обязательно в каждом интерактивном компоненте
- Появление 0,2 с ease-out (Hover, Active, Focus, выбранное, открытие), пропадание 0,25 с ease-out (возврат в Default, закрытие).
- Только токены: `--motion-duration-in`, `--motion-duration-out`, `--motion-easing-out`. Никаких своих `0.12s ease`.
- Шаблон: в обычном состоянии `transition-property: …; transition-duration: var(--motion-duration-out); transition-timing-function: var(--motion-easing-out);`, в `:hover`, `:active`, `[aria-pressed='true']`, `[aria-current]`, `:checked` — `transition-duration: var(--motion-duration-in)`.
- Анимируем только цвета, рамки, тени, прозрачность. Не анимируем размеры и положение.
- `prefers-reduced-motion` уже учтён в токенах — отдельно в компоненте не нужно.
- Подробно: `docs/component-rules.md`, раздел «Анимация переходов состояний».

## Типографика — классы и миксины, не компоненты
- Заголовки и текст — НЕ компонент. Глобальные классы `.text-*` (`text-styles.css`) в разметке или миксины `@include text-*` (`_text-styles.scss`) в стилях.
- Тег по смыслу (`h1`–`h6`, `p`), вид — классом: `<h2 class="text-heading-md">`.
- Никаких своих `font-size`, `line-height`, `font-weight`, `font-family`, `font` в стилях компонентов. Цвет текста — `var(--color-text-*)`.
- Мобильные размеры `display` и `heading-xl` переключаются сами через токены.
- Какой стиль где — `docs/typography.md`, в Storybook — «Основы / Типографика».
- Проверка: `npm run lint:css` (stylelint, `.stylelintrc.json`) — запускается и в GitHub при каждом pull request.

## Файлы компонента
- `lib/<имя>/<имя>.ts` — логика и свойства; `<имя>.html` — разметка (шаблон всегда отдельным файлом, `templateUrl`); `<имя>.stories.ts` — истории; стили — `styles/components/<имя>.css` (глобальные классы).
- Исключение: компоненты-атрибуты на `<button>`/`<a>` с шаблоном из одного `<ng-content />` (Button, Tag) — шаблон остаётся в `.ts`.

## Стили: чтобы не тащить лишний код
1. В компоненты подключать (`@use`) только файлы, которые сами не создают CSS: миксины и SCSS-переменные. Файлы с готовыми правилами (`.class { … }`, куски Bootstrap) — никогда.
2. Общее для многих компонентов (например, базовая кнопка `.btn`) — глобальный класс, один раз в глобальном CSS. Компонент добавляет только модификаторы.
3. Миксины — маленькие, несколько строк: `truncate($lines)`, `focus-ring`, `button-size($size)`. Не «весь компонент целиком»: миксин копируется в каждое место, где его подключили.
4. Варианты — классами-модификаторами на хосте компонента (`.like-btn--primary`), а не отдельными компонентами.
5. Не писать `style=""` в разметке. Отступы — токенами space/*.
6. Следить за бюджетом `anyComponentStyle` в `angular.json` (предупреждение с 2 КБ). Проверка сборки: `ng build --stats-json` + `source-map-explorer`.

## Компонент или миксин
- **Компонент** — если есть состояния, клики, данные или доступность: кнопка, лайк, пагинатор, поле, выпадающий список, модалка, тултип, табы.
- **Миксин или глобальный класс** — если повторяется только внешний вид на разных тегах: типографика, сетка карточек, поверхность карточки, обрезка названия, превью картинки.
- Одно поведение = один компонент. Разный внешний вид — через свойство `type`/`variant`, а не копией компонента. Пример: сейчас на сайте 5 реализаций лайка, должна остаться одна.

## Состояния и доступность
- Состояния: Default / Hover / Active / Disabled (+ Loading, где есть загрузка).
- Active = нажато и осталось выбранным (лайкнуто, выбранный таб). В коде `aria-pressed="true"` или `aria-selected`, а не CSS `:active`. В токенах суффикс `-active`, не `-pressed`.
- Фокус — браузерный. Никогда не писать `outline: none`.
- Кнопки — `<button>`, ссылки — `<a>`. Не наоборот.

## Не делать
- Не менять код разработчиков в основном репозитории сайта. Компоненты публикуем у себя, они забирают сами.
- Не использовать Angular Material.
- Не менять шкалы gray и green.
